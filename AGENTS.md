# Picket Development Guidelines

This file applies to the entire repository and guides coding assistants developing Picket; it is not the system prompt for Picket's built-in Agent. Any `AGENTS.md` inside a subdirectory applies only to that subtree.

## Getting Started

- Follow the user's current language in conversation. State clearly what was actually completed, verified, and left unverified; never present plans, existing configuration, or simulated output as implemented features.
- Keep all repository files outside `docs/` in English (including code, tests, comments, prompts, configuration files, `AGENTS.md`, and `README.md`), except the Simplified Chinese product README (`README.zh-CN.md`) and the runtime Chinese localization catalogs in `src/i18n/messages.ts`, `agent/src/i18n.ts`, and `src-tauri/src/i18n/`. Keep `README.md` and `README.zh-CN.md` synchronized when user-facing product behavior changes.
- Read `README.md` and relevant modules first; milestones and acceptance criteria follow `docs/development-plan.md`. M0–M6 feature implementation, release hardening, MVP acceptance, C-Push streamlining, Pinned Compact Mode, unified `~/.picket/` persistence with provider-connection model hierarchy & authenticated key reveal, and single-channel in-app updates are complete (repository reads, IDEA-style Local / Remote collapsible branch menu and remote tracking branch checkout, default auto-selection of normal changes with tri-state Select All, fixed repository-wide `Local Keep` group, internal exact-scope local commits, dynamic detection and controlled launch of five external IDEs, cross-process cold-restart prompt, project settings, and window/compact geometry persistence with silent v1 draft cleanup, five model providers configured once per connection with child models added on demand, `~/.picket/credentials.json` (`0600`) local credential storage with non-secret connection `keyHint`s and `LocalAuthentication`-gated full-key reveal, structured code review with user prompt context, minimalist on-demand `+ Prompt` toggle and editable pre-generated C-Push commit plans, single-path one-click C-Push split commits and Q&A recovery, pull-with-rebase, retry-push-only on push failure, controlled conflict resolution, pinned `400×~86` 2-row compact bar with permanent 3-button toolbar (`Compact`, `Pin`, `Settings`), expandable project/branch/remote/file drawers, top-left-anchored resize, and unfocused macOS notifications, single-channel in-app update checking/downloading/verification/restart in Settings → About & Updates, focus reconciliation, 1-click Model Settings jump on model errors, and bundled Pi Core live `kimi-k2.8` inference verification — see `docs/validation/m6.md`, `docs/validation/local-keep.md`, `docs/validation/cpush-streamline.md`, `docs/validation/compact-mode.md`, and `docs/validation/model-credential-sharing.md`). Keep documentation and regression tests synchronized on subsequent changes.
- Product behavior is specified in `docs/development.md`, screen hierarchy in `docs/ui-spec.md`, and the visual baseline in `docs/design/picket-mvp.tsx`. The right-side demo console and simulated auto-fix in the design prototype are not production features; never ship the prototype file directly as the production UI.
- `docs/` is maintained locally under `.gitignore`. If `docs/` is missing, explain what specification is absent and ask the user rather than inventing requirements or removing the `.gitignore` entry.
- Check `git status` first and preserve existing user changes. Committing, pushing, resetting, cleaning, and branch operations require explicit user authorization; Picket's in-product C-Push authorization rules do not authorize coding assistants to mutate this repository's Git history.

## Architecture & Responsibilities

- Initial target platform is macOS; current hardware verification is arm64. Check `package.json` for Node / pnpm versions, `rust-toolchain.toml` for Rust, and the lockfiles for exact dependency versions.
- `src/`: React + TypeScript UI organized by feature; `src/desktop/` wraps typed desktop commands and events; `src/i18n/` provides English (default) and Chinese UI localization.
- `shared/`: Shared protocols, identity contracts, and golden JSON fixtures (`shared/fixtures/` + `shared/protocol-contracts.test.ts`, mirrored in `src-tauri/src/protocol_contract_tests.rs`) between the UI, Node sidecar, and Rust; corresponding types must stay synchronized and validated on both sides whenever protocols change.
- `agent/`: Standalone Pi Core sidecar process; never execute models or store API keys inside the WebView.
- `src-tauri/`: Rust desktop coordinator responsible for Git reads, controlled writes, authorization checks, system integration, process lifecycle, and recovery. `src-tauri/src/repository/`, `src-tauri/src/models/`, `src-tauri/src/actions/`, `src-tauri/src/pi_runtime/`, `src-tauri/src/tray/`, `src-tauri/src/window_motion/`, `src-tauri/src/repo_lock.rs`, `src-tauri/src/storage.rs`, and `src-tauri/src/updater/` currently provide: reading user-selected repositories; switching local branches, checking out remote tracking branches, and jumping to existing worktrees with `branchToken` (manual new-branch and new-worktree creation were intentionally removed in favor of IDEA-style remote branch checkout); unified repository write coordination (`RepoWriteCoordinator` + `UpdateDrainGuard`); internal exact-scope local commits authorized by per-file `commitToken`s; dynamic local detection and controlled launch for five external IDEs (`IntelliJ IDEA`, `RustRover`, `WebStorm`, `VS Code`, `Cursor`); unified async atomic `~/.picket/` (`0700` dir, `0600` files with corrupt-file `.corrupt-*` backups) local persistence of UI language, per-project preferred editor and commit message language, canonical-`common_dir`-keyed `Local Keep` paths, window pin/compact geometry preferences (with single-source multi-monitor clamping in `window_motion/geometry.rs`), per-worktree extra prompts/selections (`workbench-state.json` v2), provider connections & child model catalog (`models.json` v3 with non-secret connection `keyHint`s), dedicated API credential map (`credentials.json` v1 keyed by `connectionId`), and unified Custom Action & C-Push session history (`action-sessions.json` v2, automatically migrating legacy `cpush-sessions.json`); Rust-authoritative menu bar tray state & popover (`tray/`, refreshing repositories directly in Rust without waking a hidden main WebView); `LocalAuthentication.framework` owner authentication for on-demand connection key reveal; macOS background attention notifications (`tauri-plugin-notification`) with `RunEvent::Reopen` window focus restoration; single-channel in-app updates via `tauri-plugin-updater` (`requireSignedVersion: true`, `latest.json` from GitHub Releases, Rust-only IPC without widening `capabilities/main.json`, active Git/C-Push/CustomAction drain guards, and `cleanup_for_restart` child-process cleanup before `app.restart()`); connection testing and unified tool-calling agent execution via bundled Pi Core (`runCustomAction` with modes `customAction`, `cpush`, and `resolveConflict`), including one-click C-Push split commits with live `message_user` Q&A and mid-flight cancellation, explicit "Pull & Rebase", lossless dirty-worktree backup across rebase, retry-push-only recovery, user-authorized Agent conflict resolution via `read_conflict_file` / `write_conflict_resolution`, and external IDE manual-merge reconciliation (zero-model, manual commit, and legacy `plan_cpush` paths were intentionally removed). `branchToken` never authorizes commits, and UI `scopeVersion` is never accepted as write authorization. All smoke-test harnesses are strictly gated behind `--features smoke-harness` / `VITE_PICKET_SMOKE=1` and excluded from release `.app` bundles.
- `scripts/`: Entry points for development, packaging, and verification; never concatenate shell commands in frontend components.
- `src/features/foundation/` and `src-tauri/src/foundation/` are M0 diagnostic probes. Candidate Git executors there run strictly against disposable temporary repositories and reject executable hooks; never expose them directly to user repositories without production validation.
- Split code by responsibility and colocate tests with their owning module; do not add speculative shared layers or empty directories. Never manually edit third-party dependencies, generated files, caches, or build artifacts.

## Non-Negotiable Invariants

- C-Push is the sole commit and push workflow: without a configured model, commits cannot run and the primary footer button guides the user to configure a model. When a model is configured, C-Push runs in a single click (analyzing authorized scope, splitting, generating messages, committing, and pushing) or executes a valid user-edited Preview Plan verbatim without re-planning; pause to ask only when a real decision is required, and never add mandatory confirmation dialogs to every commit. The prompt input carries user extra instructions only (shared with C-Push planning and Code Review), never raw commit messages and never widening authorized scope.
- Checkboxes express UI selection only and never mutate `.git/index`. Partially staged files default to committing only their staged hunks; unselected staged files must never leak into commits, and unstaged working-tree drafts must be preserved byte-for-byte.
- Fixed `Local Keep` paths are excluded from Select All, C-Push, Preview Plan, and Code Review unless explicitly checked by the user; they are persisted locally per repository by canonicalized Git common dir without touching `.git/index`, `.git/info/exclude`, `.gitignore`, `skip-worktree`, or `assume-unchanged`.
- `main` / `master` display a lightweight `Protected` badge inside the branch menu/drawer (without cluttering the outer header row) while allowing direct commits and pushes (if a remote branch protection rule rejects the push, preserve local commits and prompt to switch branches); detached `HEAD` must switch to a local branch before committing; never auto-force-push, discard user modifications, or rewrite published remote history.
- Rust is the sole controlled Git write entry point, and Git is the source of truth. Neither the UI nor the model may declare a commit successful on its own, and `git add -A` must never replace exact scope construction.
- Asynchronous tasks bind `repositoryId`, `worktreeId`, `sessionId`, `requestId`, and `scopeVersion`; switching views, retrying, cancelling, or receiving late responses must never cross targets, widen permissions, overwrite newer prompts/plans, or duplicate commits. Outdated Preview Plans (`baseScopeVersion !== scopeVersion`) must never be committed directly and are discarded on C-Push in favor of fresh planning.
- When pushing fails after local commits succeed, preserve completed commits (and preserve the prompt text) and retry pushing only. Recovery after interruption must reconcile against live Git history first instead of blindly re-running from step one.
- While the user is typing extra instructions or editing a Preview Plan message, incoming messages must never steal focus, auto-expand over the editor, or alter user text. Expanded message cards cover only the lower workspace.
- The Agent may modify conflicted files only after the user explicitly authorizes conflict resolution for the active conflict; code review findings never authorize automatic edits to business source files.
- Store all local Picket persistence inside `~/.picket/` (`0700` directory, `0600` atomic files), keeping API keys strictly separated in `~/.picket/credentials.json` (`v1`, keyed by `connectionId`; Ollama never writes to `credentials.json`). `models.json` (`v3`) stores provider connections (immutable `provider` + optional `baseUrl`, mutable `name`, and non-secret `keyHint`) and child models referencing `connectionId`; opening Settings, cold hydration, and child model CRUD must never read `credentials.json`. Real API keys may appear in IPC payloads only in two explicit cases: (1) provider connection create/update/test requests actively submitted by the user in the provider form, and (2) the return value of the dedicated `reveal_provider_api_key` command after Rust-initiated macOS `LocalAuthentication` (Touch ID or login password) succeeds; they must never appear in any other IPC command/event, error message, log, `models.json`, `workbench-state.json`, `action-sessions.json`, crash output, or test fixture (child model creation, editing, and testing transmit only `connectionId`). Revealed keys are held strictly in local component state for read-only display (never in global state, persisted drafts, URLs, logs, or sidecar payloads) and must be hidden and cleared from frontend memory immediately when 30 seconds elapse, when the reveal button is clicked again, when the form closes or switches connections, or when the window loses focus. Never reuse a developer's local Pi login or auto-load external host resources into the product Agent.
- In-app updates run exclusively on a single GitHub Releases channel (`latest.json`) mediated by Rust commands in `src-tauri/src/updater/` with `requireSignedVersion: true` Ed25519 signature verification; never add `updater:*` or `process:*` permissions to `src-tauri/capabilities/main.json`, never accept arbitrary update or browser URLs from frontend IPC, and never commit updater private signing keys. Refuse in-app installation/restart while any Git write or C-Push operation is active or when running from a dev build, read-only DMG volume, AppTranslocation path, or unconfigured signing key, and always run `cleanup_for_restart` before restarting so bundled Pi processes and temporary IDE diff directories are cleanly terminated.

## Development & Verification Commands

Run from the repository root with `pnpm` (do not create lockfiles from other package managers):

```bash
pnpm install --frozen-lockfile
pnpm desktop dev          # Desktop development; `pnpm dev` is browser preview only
pnpm desktop fmt          # Format Rust sources
pnpm check                # TypeScript typecheck, Node tests, Rust fmt/clippy, and Rust tests
pnpm ui:verify            # Headless Chrome interaction suite using isolated fixtures (no real Git or live model)
pnpm desktop build        # Build macOS application bundle
pnpm package:verify --ui   # Verify latest .app bundle, disposable Git reads, IDE diff export, branch/worktree switching, exact-scope commits, cold-restart recovery, ~/.picket/ local credential storage, Pi generate/review, C-Push split/push, and conflict merge (requires desktop session; opens and closes window)
```

- `scripts/desktop.mjs` prepends `~/.cargo/bin` explicitly; do not modify the user's shell profile to run checks.
- For standalone browser fixture previews without the desktop shell, run `pnpm dev` and open `http://127.0.0.1:1420/dev.html?scenario=question` (or `scenario=foundation` for the M0 diagnostic harness); development fixtures are excluded from production builds. `pnpm ui:verify` requires a local Chrome binary (override via `CHROME_PATH`) and uses an isolated temporary user profile.
- All Git tests must run against temporary repositories and local `bare` remotes; never run destructive Git tests against this repository or user business repositories.
- After modifying UI, state, Rust, or shared protocols, run relevant tests and `pnpm check`. When changing packaging, process lifecycle, bundled runtimes, or dependencies, also rebuild and verify the macOS `.app` bundle. Explicitly list any check that could not be executed.
- Both Node tests and desktop checks write to the same sidecar staging directory; never run commands that invoke `sidecar:prepare` in parallel.
- Report test fixtures, scripted local providers, and live online model services separately; a single passing command does not imply full MVP acceptance. Historical validation records live in `docs/validation/`.
- Preserve M0 regressions covering scope preservation, idempotency, cancellation timing, and child-process cleanup on exit; never weaken lints, skip Git hooks, or relax acceptance assertions to mask failures.

## Serena & Repository Maintenance

- Serena project configuration lives in `.serena/project.yml`, supporting TypeScript / TSX / JavaScript and Rust. Pi uses `.pi/mcp-adapter.json`, Codex uses `.codex/config.toml`, and Antigravity uses the workspace plugin `.agents/plugins/picket-serena/` (`plugin.json` + `mcp_config.json`); no root-level Serena server entry is defined. Always resolve paths from the active checkout without hard-coding machine usernames or stale directories.
- Pi runs Serena with the `agent` context, Codex with `codex`, and Antigravity with `antigravity`. Each client spawning its own Serena process is expected; do not add duplicate root entries or copy Pi-specific lifecycle fields into Codex or Antigravity configs.
- Prefer Serena for symbol and reference lookup when connected, then read targeted implementations; fall back to `rg` and file reads when unavailable, and never claim Serena is connected merely because config files exist.
- Serena respects `.gitignore`. `docs/` and design prototypes are excluded from symbol indexing — read them directly with file tools rather than treating empty symbol results as missing files.
- Keep caches, logs, memories, and `project.local.yml` local-only; shared configs and this file may be included in future commits when authorized, though tasks do not authorize committing on their own.
- After modifying Serena configs, verify symbol/reference resolution across both TypeScript and Rust (`~/.cargo/bin` and `~/.local/bin` must be on `PATH` for indexing and health checks: `PATH="$HOME/.cargo/bin:$HOME/.local/bin:$PATH" serena project index .` and `serena project health-check .`). First-run language server downloads are acceptable, without altering global user preferences or other projects.
- Summarize completed changes, verification outcomes, and remaining limitations when done. Confirm with the user before changing frozen UI specs, permissions, target platforms, or milestone scope.
